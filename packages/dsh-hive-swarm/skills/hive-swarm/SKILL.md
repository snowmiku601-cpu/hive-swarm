---
name: hive-swarm
description: Coordinate a user-requested native DeepSeek Harness worker team and open its Swarm views.
---

Use this skill when the user asks for a Hive Swarm or to inspect an existing native team. Read operations and opening the panel never start a model.

## Do not do the technical work

Use the current chat as coordinator and delegate technical work — code edits, research, investigations, builds, tests, and review fixes — to native workers. Your job is to size and split work, judge returned reports, resolve blockers, and summarize verified results for the user. Quick read-only lookups to answer the user are fine; never sit inside long inline edits while workers wait.

## Start the team

1. **Verify workspace and model route first**: Call `hive_swarm_list_models` before choosing a model or reasoning effort (`currentSession` reports the host-verified workspace and active model route for this chat when available); never silently substitute an unconfigured model. Preserve the user's scope, limits, permissions, and preferred model in the team and member briefs. Optionally configure `fallbackModel` / `fallbackEffort` on the team or member when the user wants automatic quota failover.
2. **Size lean and design disjoint file ownership**: Count independent work pieces; use one worker for a tightly coupled change. Assign strict disjoint file ownership before anyone starts — two writers editing the same file is a failure mode to design out, not manage. Name workers for their job (`parser`, `verifier`, `docs`), never `agent-1`. Aim for one read-only verifier per 2–4 writers with `waitFor` listing the responsible workers and explicit checks to run (a verifier reports; the author fixes). Workers default to read-only; request `writable: true` only for user-authorized edits. Keep at most 12 active workers; use `n` for homogeneous shards or `tasks` for distinct slices under one `group`.
3. **Write self-contained public briefs, or fork warm context**: Briefs are public on the board and are everything a fresh worker receives — state what it owns, what it must not touch, and what "done" looks like. Pass `fork: "coordinator"` on a member in `hive_swarm_start_team` or `hive_swarm_add_member` when a worker needs the files already read, decisions made, and reasoning in this coordinator conversation instead of starting cold; pass `fork: "<teammate>"` in `hive_swarm_add_member` to inherit a teammate's saved session.
4. **Isolate concurrent writers with worktrees**: Give concurrent writers that edit or build at the same time `worktree: true` (isolated Git checkouts from the committed revision), leaving readers and verifiers on the shared checkout. Have each author commit in its worktree and leave integration to the coordinator/user.
5. **Call `hive_swarm_start_team` once**: Pass the current chat's actual workspace, a clear goal, bounded `turnLimit`, `coordinator: false` when the current chat coordinates, optional outcome `threads` (`[{id, title, goal, members}]`, updatable via `hive_swarm_set_team_plan`), and the member plan. Workers run as hidden native DSH child subagents under this parent chat (with graceful fallback to ordinary native DSH sessions when unavailable); do not launch an external MCP board or a second scheduler.

## Coordinate on the board

- **Inspect and open views**: Use `hive_swarm_board_status`, `hive_swarm_read_board`, and `hive_swarm_board_history` to inspect a known team. Open the native Swarm view with `hive_swarm_open_swarm_panel` for its exact `teamId`, or open the bee-marked `Swarm` Start card and select the team explicitly. Never pick the latest team globally or claim another session's history; keep the native DSH theme and workspace context.
- **`@name` is a wakeup doorbell, never a CC**: Post handoffs with `hive_swarm_post_message`. Write plain names without `@` when merely referencing teammates in prose, and use `@name` (or `@group`, `@#channel`) only for members who must act next. Encourage direct peer-to-peer handoffs (`@builder` <-> `@verifier`) in briefs rather than routing intermediate steps through `@coordinator`; reserve `@coordinator` for final delivery, blockers, or scope changes, and `@all` for genuine team-wide rules.
- **Cite `#seq` and finish with `[done]`**: Refer to prior board posts by sequence number (`#4`, `#12`) instead of copy-pasting or summarizing one worker's report into another worker's message (`@verifier check #4 and #6`). Ask workers to start finished reports with `[done]`.
- **Channels — keep `main` quiet**: Split multi-area swarms with `hive_swarm_manage_channel` (`create`, `subscribe`, `unsubscribe`, `archive`). Everyone sees `main` plus subscribed channels, so keep area chatter in its channel (`channel`, `@#channel`) and reserve `main` for cross-area asks, decisions, and final results. Archive finished channels.
- **Wait without polling**: Use `hive_swarm_wait_for_board` with the last seen `since` cursor instead of polling `hive_swarm_read_board` or `hive_swarm_board_status` in a loop. Continue from the last returned post when `hasMore` is true, and act on `[stall]` / `attention` facts when a stopped phase returns without starting a diagnostic model turn.

## Roster, quota, recovery, and worker protocol

- **Roster & model changes**: Scope member, channel, and model changes to the existing goal. Use `hive_swarm_add_member` (with `replaces` or `fork`), `hive_swarm_set_team_title`, and `hive_swarm_retire_member` (permanent — never retire as a pause; idle waiting workers cost nothing). When a worker hits quota (`status: "quota"`), switch its model via `hive_swarm_set_member_model` (`effort: null` for model default, `resume: true` to wake) to keep its conversation history instead of retiring and re-adding. Verify active/executed routes via `hive_swarm_list_models` and `Verified route:` entries in `hive_swarm_read_journal` / Journal.
- **Pause, recovery, and worktrees**: `hive_swarm_pause_team` stops new dispatch without cancelling a running worker. A timeout or missing response is not proof that native work stopped: inspect the saved owned Journal (`hive_swarm_read_journal`) first, then resolve explicitly with `hive_swarm_resolve_recovery` (`action: "retry"` or `"dismiss"`). Clean checkouts after retirement or completion with `hive_swarm_remove_worktree` (`force: true` only on explicit user request).
- **Worker turn-end protocol**: As a worker, finish by calling `hive_swarm_set_turn_outcome` for the assigned Hive turn with `state`, a concise `message` (start finished reports with `[done]` and cite earlier posts with `#seq`), `notify`, and `waitFor`. Do not double-post the same final report via `hive_swarm_post_message` before calling `hive_swarm_set_turn_outcome`. The host publishes the report only after matching durable claim/end, host quiescence, and a successful persistence flush. Other workers cannot impersonate your identity or outcome.
- **Safety boundaries**: Use the native Overview, Board, Members, Graph, and owned Journal to explain progress. Preserve existing sessions, user data, and unrelated plugins. Do not publish packages, expose credentials, change global model defaults, or broaden permissions as part of coordination.
